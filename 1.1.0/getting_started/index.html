    Getting started

    Signalbot uses signal-cli-rest-api to communicate with Signal. The first step is to set it up. Then signalbot can run in its own python environment.

    It is also possible to mock having signal-cli-rest-api running. Check out how in the mock_chat section.

    Setup signal-cli-rest-api¶

    1. Install docker

    2. Run signal-cli-rest-api in normal mode. 

      docker run -p 8080:8080 \
    -v $(pwd)/signal-cli-config:/home/.local/share/signal-cli \
    -e 'MODE=normal' bbernhard/signal-cli-rest-api:latest

    3. Open http://127.0.0.1:8080/v1/qrcodelink?device_name=local to link your account with the signal-cli-rest-api server

    4. In your Signal app, open settings and scan the QR code. The server can now receive and send messages. The access key will be stored in $(PWD)/signal-cli-config.

    5. Stop the container and start it again in json-rpc mode. 

      docker run -p 8080:8080 \
    -v $(pwd)/signal-cli-config:/home/.local/share/signal-cli \
    -e 'MODE=json-rpc' bbernhard/signal-cli-rest-api:latest

    6. The logs should show something like this. Confirm that the server is running in the correct mode by visiting http://127.0.0.1:8080/v1/about. 

      ...
time="2022-03-07T13:02:22Z" level=info msg="Found number +491234567890 and added it to jsonrpc2.yml"
...
time="2022-03-07T13:02:24Z" level=info msg="Started Signal Messenger REST API"

    Setup signalbot¶

    1. Install signalbot in your venv of choice. 

      pip install signalbot

    2. Save the code below as bot.py.

      import logging
import os

from signalbot import (
    Command,
    Config,
    Context,
    SignalBot,
    enable_console_logging,
    triggered,
)


class PingCommand(Command):
    @triggered("Ping")
    async def handle(self, context: Context) -> None:
        await context.send("Pong")


if __name__ == "__main__":
    enable_console_logging(logging.INFO)

    bot = SignalBot(
        Config(
            signal_service=os.environ["SIGNAL_SERVICE"],
            phone_number=os.environ["PHONE_NUMBER"],
        )
    )
    bot.register(PingCommand())  # Run the command for all contacts and groups
    bot.start()

    3. Run the bot.py script.

      Pass the following environment variables to make the example run:

      • SIGNAL_SERVICE: Address of the signal service without protocol
      • PHONE_NUMBER: Phone number of the bot
      export SIGNAL_SERVICE="127.0.0.1:8080"
export PHONE_NUMBER="+49123456789"
python bot.py

      By default, SignalBot starts with HTTPS/WSS and will fallback to HTTP/WS if needed. This behaviour can be changed by setting the connection_mode in the Config argument of the bot.

    4. The logs should indicate that one "producer" and three "consumers" have started. The producer checks for new messages sent to the linked account using a web socket connection. It creates a task for every registered command and the consumers work off the tasks. If your bot has many blocking function calls, adjust the number of consumers such that the bot stays reactive. 

      <date> signalbot [WARNING] - __init__ - [Bot] Could not initialize Redis and no SQLite DB name was given. In-memory storage will be used. Restarting will delete the storage! Add storage: {'type': 'in-memory'} to the config to silence this error.

    5. Send the message Ping to the number that the bot is listening to. The bot (i.e. the linked account) should respond with a Pong. Confirm that the bot received a raw message, that the consumer worked on the message and that a new message has been sent.

    Mock chat¶

    You can mock receiving and sending messages to speed up development time. To do so, you can use signalbot.utils.ChatTestCase which sets up a "skeleton" bot. Then, you can send messages using the @mock_chat decorator. You can find an example implementation in tests/test_chat.py.
